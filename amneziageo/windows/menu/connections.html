Connections

Tunnel

  • “Show notifications” - tray messages about connecting and about updates of the application and of the databases.
  • “Reconnect after reboot” - connect the selected configuration when the computer starts; in the console it is survive-reboot.
  • “Reconnect automatically” and “Retry interval” - keep trying after a drop: at once, in 5, 10 and 20 s, then every interval; the interval is the longest pause between attempts. How a connect is retried: Reconnecting.
  • “Do not interfere with other VPNs” - an SSTP, L2TP, PPTP or IKEv2 connection of the built-in Windows client (and, by the adapter description, Cisco, Fortinet, OpenVPN, GlobalProtect) works alongside the tunnel as usual: the leak protection lets its adapter through, the networks it leads stay with it, the address of the server of a Windows connection goes past the tunnel, and the names under the connection’s suffix are asked from its DNS. Turn it off when the leak protection must cut everything but the tunnel. It takes effect at the next connect; in the console it is other-vpn.
  • “Update server” - where to take the new versions of the application from, see Update server.
  • “Allow several VPNs” turns on the mode of the Multiple VPN connections recipe. Under it stand the settings of how rules move between servers: “Check interval” - how often to check whether a rule should move to another server, “Checks before a switch” - after how many checks in a row without an answer the rule moves to another server, “Switch threshold” - how much faster the other server has to answer for the rule to move to it.

Update server

On the “Tunnel” tab, the row “Update server”: where the application takes its new versions from. The list holds:

  • “Default” - where the last update came from, and before the first update, where the application was installed from: GitHub or an update server; its address stands under the row;
  • the addresses of the update servers offered by the servers of the enabled configurations.

An update server is offered by an AmneziaGeo server whose panel has Client updates on. Until a pick is made by hand, the server with “On by default” in its panel is checked, and without one, “Default”. A pick by hand holds while the server is in the list: when it stops handing out updates, the check goes back to “Default”. Only the picked source is checked, on the channel from “General”; a version below the installed one is never offered. The files of an update server are taken under a certificate the system trusts or the one the server named. Patches are taken only from the source the application was installed from; from another one it downloads the whole installer. After an update from a server, that server becomes “Default”.

When the check fails, the reason stands under the row, and a mark stands by the state on the home screen:

Message What it means
The update server <host> does not answer the server is out of reach or broke the connection
The update server <host> holds no release of the channel the server has no releases on the picked channel
The certificate of the update server <host> is not the one its server named the system does not trust the certificate, and it is not the one the server named
The server <host> no longer hands out updates; they come from where the app was installed the server picked by hand left the list

Failures of GitHub do not reach this row. From the console: amneziageo settings set update-source origin|auto|<address> (auto drops the pick by hand), amneziageo status shows the source, the channel and the error.

Proxy

The application runs SOCKS5 and HTTP proxies through which devices without a client of their own reach the tunnel: a TV, a phone, a console.

  • “Allow connections” turns the proxy on: programs on this computer and devices on the local network use it.
  • The ports are set separately: “SOCKS5 port” and “HTTP port”. The address at which the proxy is reachable on the network stands beside them, and a button copies it.
  • Access is by “Accounts” (“User” and “Password”, any of them will do) or through “Connect without a password”: then the proxy is open to any device on the network. With no account and without that switch nobody can connect.
  • “Clients” shows who is connected and how many connections each holds.

A proxy set in the network settings is followed by the browser and by programs that reach the network through the system. Telegram on a phone is not one of them: the phone’s address and the SOCKS5 port go into Telegram itself (Settings - Data and Storage - Proxy Settings, type SOCKS5). The proxy carries TCP connections; datagrams (UDP) of neighbouring devices do not pass through it.

Traffic reaches the tunnel only while the tunnel is up.

Step by step: the Devices on the network through the proxy recipe. From the console: amneziageo proxy show, amneziageo proxy on [--socks <port>] [--http <port>] [--anon on|off] [--auth <user:password>]... [--auth off], amneziageo proxy off.

Access point

The “Wi-Fi” tab. “Access point” turns sharing on: the computer shares Wi-Fi, and the devices joined to it reach the internet through it - with the tunnel up by its rules, so the same goes into the tunnel as for the computer itself, and without the tunnel directly. “Network name” - up to 32 bytes, “Password” - from 8 to 63 characters, and the button beside it shows it. “Band” - “Auto”, “2.4 GHz” or “5 GHz”; when the adapter picked the band itself, the line under the field says which one the network runs on. “Devices” lists the ones joined. The access point has a switch of its own, apart from the proxy.

Sharing goes through the Windows service “Internet Connection Sharing”: when it is stopped, the tab says so. A Wi-Fi adapter that can share is needed.

Step by step: the Sharing the VPN over Wi-Fi recipe. From the console: amneziageo hotspot show, amneziageo hotspot on [--ssid <name>] [--password <password>] [--band auto|2.4|5] [--hidden on|off], amneziageo hotspot off.

Subscription auto-refresh

Configurations from subscriptions refresh themselves: the agent reads the subscriptions again every 12 hours unless the panel set a term of its own, and a configuration changed in the panel applies at the next connect. There is no separate setting in the window. To refresh every subscription now, use the “Refresh configs” button in the configuration catalogue. From the console: amneziageo settings set subscription-auto-refresh-enabled on|off turns refreshing on and off, amneziageo settings set subscription-refresh-interval-hours <1-168> sets the term in hours; subscriptions are managed with amneziageo sub list, amneziageo sub add <url> [<name>], amneziageo sub refresh [<name>], amneziageo sub remove <name> [--configs].
