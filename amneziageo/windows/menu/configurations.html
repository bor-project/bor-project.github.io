Configurations

Catalogue

Configurations stand as cards: the name, the latency of the server, labels - “MTU auto” or “MTU 1420”, the name of the subscription the configuration came from - and the “Selected” mark on the selected one. The “In use” switch picks the configuration for the next connect, and in the multiple-VPN mode it connects and disconnects the server; the “Connect” link brings the tunnel up on it at once, “Settings” opens its page, and “Reorder” in the menu of the card moves the cards around.

“Check” measures the latency of every server at once, past the tunnel. The card shows the time in milliseconds, “no answer”, “unreachable” when the server has no address, or “hidden by the tunnel” when the tunnel is up on another configuration and takes the probe into itself. The card of the connected server shows the latency of the tunnel itself. “Refresh configs” reads every subscription again at once, without waiting for its time. When a subscription brought a new version of a configuration while the tunnel runs on the old one, the home screen says “Configuration update available”: it applies at the next connect.

Adding a configuration

“Add” in the catalogue and “Add configuration” on the home screen offer a way:

  • “Load file” - a .conf file or a picture with a QR code.
  • “Paste” - from the clipboard: the text of a wg-quick configuration, a vpn:// link or an http(s) subscription address. The application recognises a subscription address itself, reads it and loads the configurations it hands out, and then keeps them fresh, see Subscription auto-refresh. An address without encryption is marked with a warning: the keys from the subscription travel as plain text. An address that is not served by an AmneziaGeo panel is not added: the application answers “subscription … is not from an AmneziaGeo panel” and writes a warning to the log.
  • “Scan QR code” - with the camera, where there is one.
  • “Create manually” - an editor of wg-quick text; the [Interface] and [Peer] sections are required.

A configuration file or a picture with a QR code can be dragged into the window. A transfer file dragged in is not imported by the window but sent on to the import window.

A configuration with a parameter the engine does not know is turned down with a message that a newer version of AmneziaWG is needed. A shared settings file from another device - configurations and routing lists together - is imported through “Import / export” in General.

Configuration settings

The page of a configuration opens with the “Settings” link on its card. “Configuration name” - under it a configuration from a subscription shows the name of the subscription, the time of the last refresh and a “Refresh” button that reads the subscription now. “Configuration text” is hidden behind the “Show” button: it is the wg-quick text as it is saved, read only. The name is saved with the “Save” button at the bottom of the page. Further down the same page stand the transport settings, see Transport.

The text of a configuration, its DNS for the names that go directly and exclusions are changed from the console: amneziageo config edit <name> ..., amneziageo config dns <name> [<servers>] and amneziageo config exclusions <name> ...; the tunnel takes the new text at the next connect.

Export

“Export” on the page of a configuration shows a QR code in one of the views: “QR file” - the content of the .conf, “QR link” - a vpn:// link, “Subscription” - the subscription address of a configuration that came from one. “Copy” puts the text on the clipboard, “Download QR” saves the picture. The QR code contains the private key: do not show it to others. A long configuration does not fit into a QR code, and then the text or the vpn:// link is what remains. From the console the link is printed by amneziageo config link <name>.

Deleting

“Delete configuration” at the bottom of the page asks for a confirmation; a deletion cannot be undone. A configuration from a subscription comes back when the subscription is refreshed, as long as the subscription hands it out; the whole subscription is removed by amneziageo sub remove <name> --configs.

Transport

The transport settings on the page of a configuration: “Proxy” (WebSocket, see below), “MTU”, “DNS”, “IPv6”, “Routing”, “Hold traffic when the tunnel drops”, “Allow incoming connections from the VPN network”, “Allow the server to disconnect the tunnel”.

  • “MTU” - the packet size of the tunnel: “Auto” - the largest that passes the link, but not above the one declared in the configuration, “Config” - exactly the MTU line of the configuration, “Manual” - a number from 1280 to 1500. The value in force stands as a label on the card. From the console: amneziageo config mtu <name> auto|config|<number>.
  • “DNS” Only with an AmneziaGeo serverThe Server item asks the DNS server of the AmneziaGeo panel inside the tunnel.Learn more - who the names that go through the VPN are asked of: “Default” - what the AmneziaGeo server of this configuration picked, the DNS line of its text otherwise; “Network” - the DNS of the network of the device, past the tunnel; “Server” - the DNS server of the server itself inside the tunnel, available when the server offers it; the choice is known to this client alone, and when the DNS server of the panel stops (the “Automatic” mode with no rules by name), at the next connect the names go as with “Default”; “Custom” - the addresses of the field, one of them IPv4, an empty field means 1.1.1.1, 1.0.0.1. The field beside shows in grey what the choice settles on. It takes effect at the next connect. From the console: amneziageo config vpn-dns <name> default|network|server|own [<servers>].
  • “IPv6” - whether the tunnel carries IPv6; off by default, see Limitations.
  • “Routing” Only with an AmneziaGeo serverThe AmneziaGeo server keeps this configuration to its own routing lists.Learn more - whether the selected routing list applies to this configuration. With the switch off the tunnel follows the AllowedIPs of its text. From the console: amneziageo config routing <name> on|off. For a configuration whose server allows none but its own lists the switch is on, not available and marked with the AmneziaGeo sign, see What the server offers.

WebSocket Only with an AmneziaGeo serverAn AmneziaGeo server names the WebSocket front itself: no address or port to type.Learn more

AmneziaWG runs over UDP, and on some networks - corporate and guest Wi-Fi, some mobile carriers - it does not get through. The whole tunnel can then run over a WebSocket on TCP: from the outside it looks like ordinary HTTPS traffic.

An AmneziaGeo server that answered offers its front itself: the host of the Endpoint of the configuration at the port of its services. By default that is the port of the Endpoint, or the one in the line # AmneziaGeo Services = <port> when the server moved its services. The front is dialled under TLS, and the server knows the configuration by a token counted from its keys, so the certificate is not checked. A server of ours that offers no front keeps the WebSocket switch closed.

An older AmneziaGeo server names its front in the configuration it hands out, in the line # AmneziaGeo WebSocket = wss://<host>:<port>/<path>, and that front is taken as it stands.

For any other server the front is set in the settings: an address and a port, and a login and password or a token if the server requires authentication. An empty address and port take the host and the port of the Endpoint; an address or a port that does not hold counts as empty. Such a front is dialled under TLS with its certificate checked. Turning WebSocket on stays with you. From the console: amneziageo config websocket <name> on|off [--host <address>] [--port <port>].

Hold traffic when the tunnel drops

While the tunnel reconnects, what is selected does not go directly. How it acts: Holding traffic when the tunnel drops.

Incoming connections from the VPN network

By default the client answers nothing that arrives from the tunnel: what it opened itself keeps working, and the rest is dropped. Access is granted per configuration and has three states:

State Who may reach this machine
off nobody, and that is the default
the server the gateway of the tunnel alone, the first address of the tunnel network
the whole tunnel network every address of the tunnel network

In the console it is one command, and config list prints the state in the INBOUND column:

amneziageo config inbound <name> off|host|network
amneziageo config list

host stands for the server, not for this machine: the word names the gateway the configuration dials. In the app the switch sits on the transport tab of the configuration.

The server has to allow it too: a server of AmneziaGeo keeps its own switch per client, and until both sides agree nothing gets through. A port forwarded on the server also needs the client to take what arrives.

The access is collected when the tunnel comes up, so the app raises the reconnect mark and the new state stands from the next connect.

Allow the server to disconnect the tunnel Only with an AmneziaGeo serverAn AmneziaGeo server takes the tunnel of this device down when the client is turned off in the panel.Learn more

The server takes the tunnel down when this client is turned off on the server. The switch is available while the panel of the AmneziaGeo server of this configuration has turned the signal on for this client; with another server or without the signal it is off and not available, and the choice made before is kept. How it acts: Holding traffic when the tunnel drops.

What the server offers

The application asks an AmneziaGeo server what it offers a configuration: when the window opens, after a configuration is added or edited, after a subscription or a bundle brings a configuration whose server was not asked yet, and before a connect. The first connect of a configuration, and one after its Endpoint or keys changed, waits for the answer; later connects take the kept answer at once, and a server of ours is asked again behind the connect once a day. The question goes over TCP to the host of the Endpoint at the port of the services; the application proves the keys of the configuration, and the answer is sealed for it alone.

The answer is kept per configuration: the WebSocket front and where the speed is measured. The answer also hands out the geo sources of the server and the routing lists the template of the client names. The application adds a source it holds none of at that address, moves a source it holds under the same name to the address of the server, once per address, and fetches these sources at once; a source the owner removed comes back with the next answer.

A list of the server is known by its identifier. One the application holds none of is added, and put in use when the server marks it on by default and no list is in use. One it holds stays as it is; when the server changed it since, its card and the title of the open list show Update, and pressing it takes the name, the rules and the traffic switches of the server in place of what the list held, in use or not as it was. A list the owner removed comes back with the next answer.

A list the server keeps “Read-only” is marked “Read-only” on its card and at the title of the open list. It cannot be renamed, changed or removed, neither in the window nor from the console (“The list “…” is read-only: it comes from the server of …”); it can be turned on and off. A newer version of the server takes its place itself, without Update, and the open list is read again. The server took the flag off: the list can be changed again, and a newer version waits for Update; the server put the flag back: a list that was changed takes the version of the server; the server no longer hands the list out: it stays an ordinary one.

A server that lets a configuration use none but its own lists (“Server lists only” in the template of the client) limits the choice while that configuration is connected. At the connect an own list in use, or no list, gives way to the list of the server marked on by default, else to the first one, and the “Routing” switch of the configuration is turned on. While it stays connected, “In use” of the other lists and of the list of the server in use is not available, nor is the routing switch of the home screen, and the hint names the configuration: “The server of … allows none but its own routing lists”. From the console picking an own list and none are refused with the same words, and routing list names the lists allowed. The flag taken off or the configuration disconnected, the choice of the list is free again and the list in use stays. With several VPN connections the lists of the first connected configuration with the flag, in the order of the set, hold.

The “Routing” switch on the page of the configuration stays locked longer: as long as the server holds the flag it is on and not available, with the same hint, connected or not, and config routing <name> off is refused with the same words. The flag taken off, the switch is free again.

The card of a list names where it came from: the configuration it arrived with, with the sign Only with an AmneziaGeo serverThe list came from the AmneziaGeo server of the configuration named on the card, and new versions come from it too.Learn more before it, or Local for a list made on the device. A server older than the identifiers has its lists added by name and none of them put in use.

A server of another kind, or a silent one, changes nothing. A server of ours stays one until it answers as a server of another kind three times in a row, or once when a subscription is refreshed; a port that refuses the connection counts as such an answer. A question that gets no answer (a timeout, a name that does not resolve, a TLS that fails, an error of the server) changes nothing, and the server is asked again after a pause that doubles from a minute up to a day. A server that answered the last question as a server of another kind is asked in the background before a connect, and the connect does not wait for it. A server that never answered is not taken for one of another kind: the next three connects wait for it again, three seconds at most each, and after them it is asked in the background too.

A tunnel that stands inside a WebSocket has its server asked again. When the front refuses the tunnel, the question goes at once, and an answer that names another port or path has the tunnel carried there while it stays up. When the tunnel carries nothing, the question goes with every repair, and an answer that offers no front any more has the tunnel raised again without the WebSocket.

A subscription read at its address is proven by the certificate of its server: by the store of the device, or by the roots of Let’s Encrypt the application carries for a device whose store lacks them.

The server side, the panel, is described in its repository: amneziageo_server.

AmneziaGeo mark

A blue disc with the power sign stands beside what works only with an AmneziaGeo server:

  • “Proxy”: the server names the WebSocket front itself, see WebSocket;
  • “DNS”: the “Server” item, see Transport;
  • “Routing”, while the server keeps the configuration to its own lists;
  • “Allow the server to disconnect the tunnel”, see Allow the server to disconnect the tunnel;
  • the card of a list that came from the server: the mark stands before the name of the configuration, see List card;
  • “Data transfer speed test service”, see Probe settings.

The mouse pointer resting on the mark opens a window, a press holds it open: what an AmneziaGeo server gives and how it stands for this configuration - its server is AmneziaGeo with this feature, AmneziaGeo without it, or not AmneziaGeo or has not answered yet. A press on the mark leaves the switch beside it alone.

On the pages of this site the mark stands beside the same settings and opens a window with the same text. The server panel puts the same sign beside what reaches only the AmneziaGeo app, see AmneziaGeo mark on the server site.
