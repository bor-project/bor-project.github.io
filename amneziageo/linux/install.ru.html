Установка

Две части из одного дерева исходников:

  • amneziageo - агент службой systemd, движок AmneziaWG и консольный клиент amneziageo с полноэкранным интерфейсом. Графических библиотек не тянет, годится серверу без рабочего стола.
  • amneziageo-gui - графический интерфейс. Работает от пользователя рабочего стола, управляет тем же агентом через его контрольный сокет и требует amneziageo той же версии.

Серверу нужен только первый пакет, рабочему столу - оба. Всё, что настраивается в графическом интерфейсе, доступно и из консольного клиента.

Установщик

Скрипт берёт нужные машине пакеты прямо из свежего релиза:

curl -fsSL https://raw.githubusercontent.com/bor-project/amneziageo/master/amneziageo-linux/tools/install.sh | sudo bash

Архитектуру он читает из dpkg, каждый пакет сверяет с SHA-256 из update.json и отдаёт apt. Ключи: --no-gui (только агент), --tag v1.2.3.4 (конкретный релиз), --prerelease, --repo owner/name.

С терминала он спрашивает, поставить ли короткую команду консольного клиента и как её назвать, по умолчанию ag-c: это ссылка /usr/local/bin/ag-c на /usr/bin/amneziageo, и ag-c status делает то же, что amneziageo status. Имя, занятое другой программой или командой оболочки, скрипт не трогает и спрашивает другое. --shortcut <имя> ставит ссылку без вопроса, --no-shortcut ничего не спрашивает, без терминала ссылка не ставится. Повторный запуск оставляет найденную ссылку, удаление пакета её убирает.

Пакеты вручную

Возьмите пакеты своей архитектуры со страницы Releases - собираются amd64 и arm64 - и поставьте через apt, он подтянет названные ими библиотеки:

# сервер
sudo apt install ./amneziageo_<версия>_amd64.deb

# рабочий стол
sudo apt install ./amneziageo_<версия>_amd64.deb ./amneziageo-gui_<версия>_amd64.deb

Агент сразу запускается; в автозагрузке он стоит, пока включён survive-reboot. Бинарники лежат в /usr/lib/amneziageo, библиотека - в /var/lib/amneziageo, клиент - /usr/bin/amneziageo, имя интерфейса агент берёт из /etc/default/amneziageo. apt о короткой команде не спрашивает: её ставит sudo ln -s /usr/bin/amneziageo /usr/local/bin/ag-c, удаление пакета её убирает.

Для машины не на Debian amneziageo-linux/tools/install-server.sh публикует агент и консольный клиент из исходников прямо в /opt/amneziageo и так же спрашивает о короткой команде, ссылке на /opt/amneziageo/amneziageo.

Дальше - первая конфигурация.

Запуск и остановка

sudo amneziageo start    # запустить агента
sudo amneziageo stop     # остановить его и опустить туннель
amneziageo daemon status # работает ли, стоит ли в автозагрузке, есть ли сокет

Автозагрузка агента следует за survive-reboot: агент включает или выключает свой юнит при старте и при каждой смене настройки - из консоли, полноэкранной консоли или окна. С выключенной настройкой после перезагрузки агент не работает, пока не выполнить sudo amneziageo start.

Права агента

Агент работает от root: он создаёт устройство туннеля и правит маршруты, одного CAP_NET_ADMIN его проверке недостаточно. Управляющий сокет - /tmp/CoreFxPipe_AmneziaGeo.Agent, поэтому в юните нельзя включать PrivateTmp; любая локальная учётная запись, дотянувшаяся до сокета, управляет агентом и читает ключи конфигураций.

Обновление

Пакет несёт в себе адрес манифеста релизов, поэтому приложение обновляет себя само: окно предлагает новую версию, агент берёт ровно те пакеты, что стоят на машине, под её архитектуру и отдаёт их apt из временного юнита, который переживает перезапуск самого агента. Если установлен предыдущий выпуск, на каждый пакет качается одна дельта с файлами, изменившимися против установленных (изменившийся файл - разностью от установленного), она сверяется с опубликованной SHA-256, и пакет собирается заново; с более старой версии, или если дельта не подошла, агент качает пакет целиком, сверяет его с опубликованной SHA-256 и после обрыва продолжает с места обрыва. То же самое из консоли - amneziageo update check. После установки перезапустите окно, чтобы обновился и интерфейс.

Docker

Агент и консольный клиент работают и в контейнере. amneziageo-linux/docker/Dockerfile собирает образ из корня репозитория под amd64 и arm64; контейнеру нужны NET_ADMIN и /dev/net/tun.

cd amneziageo-linux/docker
mkdir -p configs && cp ~/work.conf configs/
AMNEZIAGEO_CONNECT=work docker compose up -d --build
docker compose exec amneziageo amneziageo geo download
docker compose exec amneziageo amneziageo tui

Каждый configs/<имя>.conf при старте импортируется под именем файла, а AMNEZIAGEO_CONNECT подключается на одном из них и держит туннель после перезапусков. Библиотека лежит в томе, журнал агента выводит docker compose logs.

  • compose.yaml - у контейнера своя сеть. Другие сервисы входят в неё через network_mode: service:amneziageo и ходят туда, куда их отправляет список маршрутизации; при каждом перезапуске контейнера агента такой сервис теряет сеть и возвращается через docker compose up -d --force-recreate <сервис>. Локальный прокси опубликован на 10808 (SOCKS5) и 10809 (HTTP): docker compose exec amneziageo amneziageo proxy on --auth user:password. На соединения, пришедшие через опубликованные порты, ответ уходит мимо туннеля.
  • compose.host.yaml - network_mode: host: туннель, маршруты и резолвер принадлежат самому хосту. /etc хоста примонтирован, чтобы агент направил на себя resolv.conf хоста (AMNEZIAGEO_RESOLV_CONF), а системная шина со снятыми ограничениями AppArmor и SELinux - чтобы systemd-resolved, пока туннель поднят, спрашивал только агента. Рядом с установленным агентом не запускается: оба занимают один и тот же интерфейс и адрес резолвера.

Удаление

apt remove библиотеку оставляет, apt purge удаляет.
