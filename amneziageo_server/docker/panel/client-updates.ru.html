Обновления клиентов Только в приложении AmneziaGeoОбновления с сервера берёт приложение AmneziaGeo: сервер сообщает, где лежат выпуски, и приложение проверяет их там под сертификатом сервера.Другие клиенты AmneziaWG этого не получают: им доходит только файл конфигурации.Подробнее

Вкладка раздаёт приложениям AmneziaGeo ваши выпуски клиента вместо выпусков проекта на GitHub: например, сборку со своими правками или версию, которую вы проверили сами. Выпуски лежат на сервере обновлений: в самой панели («Свой») или в отдельном сервисе («Адрес», см. Отдельный сервер обновлений). Вкладку видит роль с правом «Обновления клиентов».

Раздача

«Раздавать обновления клиентам» включает раздачу и открывает её настройки, «Источник» выбирает «Свой» или «Адрес». «Сохранить» вступает в силу сразу: панель заново поднимает выпуски, а если хост не дал порт, оставляет прежние настройки и пишет причину под кнопками.

Свой

Поле Что задаёт
Директория где лежат выпуски; пусто - папка client-updates рядом с базой панели. Под полем свободное место и «чтение и запись», когда панель может туда писать
Порт пусто - порт панели: выпуски рядом с ней, под её сертификатом; другой порт - свой слушатель под сертификатом панели. Закрытый брандмауэром порт отмечается в «Службах» Обзора
Путь что идёт после порта; по умолчанию случайный, «Новый путь» делает другой. На порту панели путь не может начинаться с api, assets, пути панели или пути подписок
Токен ключ API выпусков для скриптов; видны начало и конец, «Копировать» кладёт его в буфер, «Новый токен» делает другой
Адрес для клиентов https://<хост>:<порт>/<путь>/: здесь приложения читают выпуски
Включён по умолчанию приложение, в котором сервер обновлений не выбран рукой, берёт этот сервер

Адрес

«Адрес» - адрес https:// отдельного сервиса выпусков, «Токен» - его токен: меню печатает его один раз при установке сервиса. «Проверить» спрашивает сервис сейчас и пишет «отвечает: выпусков N, объём» или «не отвечает: причина»; сама панель спрашивает его раз в 5 минут. Сертификат, под которым сервис ответил, панель запоминает и называет приложениям, поэтому сервису годится и его собственный сертификат. Выпуски сервиса в панели создаются и правятся так же, как свои. «Включён по умолчанию» - как у «Своего».

Выпуски

Таблица «Выпуски» идёт постранично: версия, канал, дата, файлы из 20 и объём. В меню строки - «Изменить» и «Удалить»; удаление спрашивает подтверждение и убирает выпуск вместе с файлами. Сами выпуски не устаревают: лежат, пока их не удалят.

Канал задаёт, кому достаётся выпуск. Приложение на канале «Стабильный» берёт стабильные выпуски, на «Бета» - стабильные и беты, на «Тест» - все; канал выбирается в «Общих» приложения. Из выпусков своего канала приложение берёт старший по версии, а стабильный выпуск выигрывает у беты той же версии. Версию ниже установленной приложение не ставит.

Новое обновление

«Создать обновление» открывает окно «Новое обновление».

  • «Версия» - четыре числа, например 1.10.16.0; «Канал» - стабильный, бета или тест; «Описание» - одна строка до 256 знаков.
  • «Файлы выпуска» - 20 имён выпуска с этой версией: установщики Windows x64 и arm64, с .NET внутри и без него (-fdd), пакеты amneziageo и amneziageo-gui для amd64 и arm64, APK Android (общий и по архитектурам), патчи к установщикам и пакетам. У каждого имени «Выбрать файл» и «Очистить», у патча - «от версии»: версия, с которой он обновляет.
  • «Подтвердить» доступна, когда выбран хотя бы один файл и ни у одного нет ошибки. Файлы уходят на сервер по одному, строка файла пишет «отправка N%».

Файл проверяется дважды. Браузер сразу сверяет имя файла с именем строки и «от версии». Сервер при загрузке читает сам файл: установщик - программа Windows нужной архитектуры, пакет - пакет Debian с нужными именем и архитектурой, APK - архив с библиотеками нужных архитектур, патч - патч к установщику или пакету того же имени. Отказ пишется в строку файла, например «собран для x64, не arm64»; файл остаётся выбранным, остальные загружаются. Размер и SHA-256 считает сервер, он же собирает update.json выпуска: версия, канал, описание, файлы с патчами.

«Изменить» открывает то же окно для выпуска: сменить канал и описание, загрузить или заменить файл, убрать файл (до подтверждения он «будет удалён»), поправить «от версии».

Архив

«Загрузить архив» открывает то же окно со строкой «Архив zip вместо файлов»: zip с файлами выпуска в корне или в одной папке. update.json в архиве не обязателен: если он есть, сервер сверяет с ним имена, размеры и SHA-256 файлов, если нет - собирает свой. Версия и канал берутся из окна, и имена файлов должны им отвечать.

Как приложение находит выпуски

Пока раздача включена, ответ сервера приложению (hello) несёт адрес выпусков, отметку «по умолчанию» и SHA-256 сертификата: у «Своего» - сертификата, под которым отвечают выпуски, у «Адреса» - того, под которым ответил сервис. Адрес «Своего» строится от имени, по которому пришло приложение. Приложение читает <адрес>/<канал>/update.json и файлы рядом с ним под сертификатом, которому верит система, или под названным. В приложении такой сервер виден в «Подключениях» - «Сервер обновлений», см. сайт клиента.

Сервер прежних версий в ответе ничего о выпусках не говорит, и его приложения берут обновления с GitHub.
