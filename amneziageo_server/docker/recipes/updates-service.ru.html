Отдельный сервер обновлений

Выпуски клиента можно держать не в панели, а на отдельном сервере обновлений: на другом хосте, на другом диске или один на несколько панелей. Это тот же сервер обновлений, что «Свой» в панели, только отдельной программой: выпуски он отдаёт приложениям без авторизации, а принимает по токену из своего окна, из панели или скриптом. Панель на своём хосте раздаёт выпуски сама, см. Обновления клиентов, поэтому на хосте стоит что-то одно: панель или сервер обновлений. В примере сервер стоит на updates.example.com, а панель берёт его выпуски по адресу.

Поставить сервер

Нужны Debian 12 и новее или Ubuntu на amd64 или arm64, права root и место под выпуски: один выпуск клиента занимает около 800 МБ. Модуль amneziawg и пересылка пакетов серверу не нужны. От root:

curl -fsSL https://github.com/bor-project/amneziageo_server/releases/latest/download/amneziageo-server \
  -o /usr/local/bin/amneziageo-server
chmod 755 /usr/local/bin/amneziageo-server
amneziageo-server install

На первый вопрос, What to install, ответьте 2 (Client updates server). Скрипт осматривает хост (система, память и диск, Docker, ufw, занятые порты, сертификаты Let’s Encrypt), задаёт вопросы, печатает план и после согласия делает всё по списку.

Вопрос По умолчанию Ключ файла ответов

принять условия использования   license
Install as: 1. Package (служба), 2. Docker 2, если на хосте есть Docker kind: package или docker
поставить короткую команду меню, её имя спрашивается только с терминала; ag-s или первое свободное имя с номером shortcut

Для Docker нужен Docker с плагином compose и работающей службой: если чего-то нет, скрипт печатает команды, которые это ставят, и выходит, ничего не меняя. Ответы можно заранее положить в файл и дать его командой amneziageo-server install --answers <файл>, как для панели.

Что делает установка:

  • обновляет систему, если согласились; если пришло новое ядро, перезагружает хост, и та же команда после перезагрузки продолжает с теми же ответами;
  • получает сертификат Let’s Encrypt на имя сервера (certbot, проверка на TCP 80, продление таймером certbot.timer) или берёт тот, что у хоста уже есть; без имени сервер отвечает под своим сертификатом, а приложения проверяют его по отпечатку, который называет панель;
  • делает токен и случайный путь окна;
  • службой: скачивает архив сервера из последнего релиза канала, сверяет его со списком релиза, подписанным ключом релизов, и ставит службу amneziageo-updates; в Docker: кладёт проект compose в /opt/amneziageo-updates и поднимает контейнер amneziageo-updates из образа ghcr.io/bor-project/amneziageo-updates того же релиза, на сети хоста;
  • открывает порт в ufw или включает ufw;
  • печатает адрес выпусков для панелей и приложений, https://<имя или адрес хоста>:<порт>/, адрес окна и один раз токен.

Где что лежит:

  Служба Docker
программа /opt/amneziageo-updates/releases/<выпуск>, ссылки current и previous образ, проект compose в /opt/amneziageo-updates
служба amneziageo-updates.service контейнер amneziageo-updates
выпуски /var/lib/amneziageo-updates тот же каталог хоста
порт и сертификат /etc/amneziageo-updates/updates.env тот же файл
токен, путь окна token, web-path в /etc/amneziageo-updates те же файлы

Дальше сервером управляют из его меню: amneziageo-server на таком хосте открывает меню сервера обновлений с обновлением и откатом, новым токеном, новым путём окна, портом, сертификатами и брандмауэром.

Без меню

Образ запускается и без меню, настройки - в переменных Updates__*:

Переменная Что задаёт
Updates__Listen__0 адрес и порт, например *:8445; не задан - порт 8445 на всех адресах
Updates__Path путь перед выпусками; пусто - корень
Updates__WebPath путь окна; не задан - файл web-path в Updates__Etc: при первом старте сервер пишет туда случайный путь
Updates__Directory директория выпусков, /var/lib/amneziageo-updates
Updates__Etc директория токена, пути окна и своего сертификата, /etc/amneziageo-updates
Updates__Token, Updates__TokenFile токен или файл с ним; не заданы - файл token в Updates__Etc: при первом старте сервер пишет туда новый токен
Updates__Certificate, Updates__CertificateKey цепочка и ключ в PEM; не заданы - свой сертификат

GET /health отвечает 204, на нём стоит проверка здоровья контейнера.

Окно сервера

Адрес окна - https://updates.example.com:8445/<путь>/: путь из 16 букв и цифр печатают установка и пункт 9 меню View Current Settings, новый путь даёт пункт 7 Reset UI Path. Вход в окно - по токену сервера.

После входа окно показывает адрес выпусков для панелей и приложений с кнопкой «Копировать», директорию выпусков со свободным местом и таблицу «Выпуски». Выпуски создаются, правятся и удаляются так же, как во вкладке панели, см. Выпуски. Окно, открытое до нового токена из меню, при следующем обращении к серверу возвращается ко входу: войти можно уже с новым токеном.

Подключить к панели

  1. «Настройки» - «Обновления клиентов»: включить «Раздавать обновления клиентам», «Источник» - «Адрес».
  2. «Адрес» - https://updates.example.com:8445/, «Токен» - токен сервера, «Проверить». Ответ - «отвечает: выпусков 0, 0 Б».
  3. «Сохранить». Панель запомнит сертификат сервера и будет называть его приложениям.

Брандмауэр хоста сервера должен пускать его порт: приложения качают выпуски прямо с сервера, а не через панель.

Положить выпуск

«Создать обновление» в окне сервера или на вкладке панели с «Адресом»: версия, канал, файлы, «Подтвердить», см. Новое обновление. Приложение с конфигурацией этой панели видит сервер в «Подключениях» - «Сервер обновлений» по его адресу; если стоит «Включён по умолчанию», приложение берёт его, пока сервер обновлений не выбран рукой, и предлагает выпуск своего канала, когда он новее установленной версии.

Проверить

  • curl -s -o /dev/null -w '%{http_code}\n' https://updates.example.com:8445/health - 204.
  • curl https://updates.example.com:8445/beta/update.json - манифест самого нового стабильного выпуска или беты; 404, пока их нет.
  • amneziageo-server status на хосте сервера: отвечает ли сервер и его окно, сертификат, порт в ufw.
  • Строка «Обновления клиентов» в «Службах» Обзора панели стоит без причины.

Контейнер рядом с панелью, поставленный пунктом 30

Раньше сервер обновлений ставился пунктом 30 меню панели в контейнер рядом с ней. Такой контейнер обслуживает тот же пункт 30: он виден в меню панели, пока контейнер стоит, и умеет перевести его на последний образ, сделать новый токен, показать журнал и снять. Первое обновление переводит контейнер на сеть хоста с тем же портом, а порт и сертификат - в /etc/amneziageo-updates/updates.env; выпуски и токен остаются прежними.
