AmneziaGeo Server

Сервер AmneziaGeo - панель управления сервером AmneziaWG на Linux. Она сама поднимает интерфейсы туннеля в ядре, ведёт клиентов и выдаёт им конфигурации файлом, QR-кодом, ссылкой vpn:// и подпиской, считает трафик, а трафик клиентов умеет направлять дальше: по гео-базам и доменам через другие серверы, через сам хост или в блок. Работает на Debian и Ubuntu с модулем amneziawg в ядре, службой или в Docker, на amd64 и arm64.

Выберите способ установки

  • Служба systemd на хосте, Debian 12 и Ubuntu, amd64 и arm64 Установка · Первый запуск
  • Docker контейнер в сети хоста, образ для amd64 и arm64 Установка · Первый запуск

Оба способа делают одно и то же: контейнер работает в сети хоста, и интерфейсы, правила брандмауэра и порты у него те же, что у службы. Поставить любой из них умеет одна команда - консольное меню amneziageo-server, оно же потом обслуживает сервер: обновления и откат, копии базы, сертификаты, брандмауэр, пользователи и токены.

Что умеет

  • Интерфейсы. Серверные интерфейсы AmneziaWG с ключами, портом, адресами и всей обфускацией профиля 3.1. Панель кладёт их в ядро сама, без awg и awg-quick, следит за ними и поднимает заново, если хост их потерял. Интерфейсы, поднятые awg-quick, переезжают в панель целиком, вместе с клиентами.
  • Клиенты. Пара ключей, адреса в туннеле, включение и выключение, заметка, ограничение трафика в день, доступ к клиенту из туннеля. Конфигурация выдаётся файлом .conf, QR-кодом и ссылкой vpn://, имя конфигурации собирается по шаблону. Список показывает, кто в сети, скорость и трафик за день. Выключенному клиенту приложение AmneziaGeo само опускает туннель по сигналу сервера.
  • Шаблоны и подписки. Шаблон задаёт клиентам AllowedIPs из гео-ключей, сетей и доменов, DNS, MTU и keepalive, а сервисы за CDN ведёт по именам через подставные адреса резолвера; правка шаблона меняет файлы всех его клиентов. Подписка отдаёт конфигурации нескольких устройств по одному адресу, клиентские приложения перечитывают её сами.
  • Маршрутизация на сервере. Правила по странам и категориям сайтов из гео-баз, доменам, адресам, портам и клиентам. Трафик уходит через канал (туннель AmneziaWG к другому серверу, в том числе внутри WebSocket), через хост или блокируется. Группы каналов: по приоритету, по кругу или по клиенту. Проверка маршрута по имени и порту.
  • Резолвер для клиентов. Сервер отвечает клиентам на DNS-запросы сам, спрашивает внешние серверы по HTTPS или TLS и кладёт увиденные адреса в наборы правил: так правила по доменам работают на уровне ядра.
  • WebSocket. Туннель внутри WebSocket на TCP-порту интерфейса для сетей, где проходит только веб-трафик.
  • Для приложения AmneziaGeo. Клиентскому приложению сервер отдаёт свои гео-источники, списки маршрутизации (пресеты), адрес подписки и замер скорости; клиент AmneziaGeo для Windows, Linux и Android читает всё это сам. Любое другое приложение AmneziaWG работает с сервером как с обычным сервером AmneziaWG.
  • Обслуживание. Обновления из панели с откатом при сбое, резервная копия базы одной кнопкой и перенос на другой сервер из неё, журнал событий и журнал подключений, консольное меню для всего, что делается на хосте.

Что потребуется

  • Linux с модулем amneziawg в ядре на amd64 или arm64: Debian 12 и новее, Ubuntu. Консольное меню ставит модуль из PPA Amnezia, если ядро его не несёт.
  • Публичный адрес или имя, по которому клиенты найдут сервер. Для панели по HTTPS нужны имя и сертификат Let’s Encrypt, его тоже выпускает меню.
  • Права root на сервере.

Разработчикам

Сборка и устройство репозитория, HTTP API.

Лицензия и благодарности

Сервер построен на экосистеме Amnezia VPN: модуль ядра AmneziaWG. Туннель внутри WebSocket несёт wstunnel. Гео-базы по умолчанию: Loyalsoldier/v2ray-rules-dat, runetfreedom, zkeen-ip и собственная amneziageo-geo.
