Утилита

Утилита - консоль сервера: она работает с той же базой, что панель, и делает то, что не делается через HTTP до первого входа, да и всё остальное из скриптов. Она лежит в релизе как /opt/amneziageo-server/AmneziaGeo.Server.Cli, а меню amneziageo-server передаёт ей команды, которых не знает само: amneziageo-server user list. Член группы amneziageo запускает её без sudo; чтение интерфейсов ядра требует root. amneziageo-server help печатает команды меню, утилита без команды - свои.

Пароль утилита спрашивает в терминале; --generate придумывает его и печатает один раз, --permanent не требует смены при первом входе. Команды, которые что-то удаляют, спрашивают подтверждение, --yes отвечает за вас.

Вход и учётные записи

Команда Что делает
init [--user <логин>] [--generate] [--permanent] первый администратор, пока в панели нет включённого; без --user - учётная запись хоста, от которой запущена утилита. Последней строкой называет порт и путь панели
login [--user <логин>] [--json] войти и напечатать токены сессии
refresh <токен> обменять токен обновления на новую пару
whoami что панель думает об учётной записи хоста, от которой запущена утилита
user list учётные записи с ролью и состоянием
user add <логин> [--role <роль>] [--host [--key <открытый ключ>]] [--generate] [--permanent] учётная запись панели; --host делает её и пользователем хоста с ключом ssh
user passwd <логин> [--generate] [--permanent] новый пароль
user role <логин> <роль> роль
user enable, disable, remove <логин> включить, выключить, удалить
role list, role add <код> [--title <название>] <право>..., role set <код> [--title <название>] [<право>...], role remove <код> [--yes] роли; права - state:read, clients:write, interfaces:write, routing:write, access:write, updates:write, backup:read, client-updates:write
token list, token add <название> --role <роль> [--days <n>], token revoke <id> [--yes] токены для скриптов; секрет печатается один раз последней строкой

Панель

Команда Что делает
panel show где отвечает панель
panel get port, path, listen, domains, certificate, key, opened, channel одно значение, для скриптов
panel set [--port <n>] [--path <путь> | random | /] [--listen <адреса> | all] [--domains <имена> | none] [--certificate <цепочка> --key <ключ> | --certificate none] [--opened on | off] [--channel stable | test] настройки вкладок «Сервер» и «Сертификаты»; --opened держит порт панели открытым в брандмауэре, --channel - канал релизов. Данная до первого старта, записывает настройки первой, см. Первый старт
panel reset [--yes] 127.0.0.1, порт 8443, новый случайный путь, без сертификата
subscriptions show, subscriptions get <имя>, subscriptions set --opened on | off подписки: показать, одно значение, держать порт открытым
update status, update check, update apply [--beta] обновление: как прошло последнее, посмотреть релизы сейчас, поставить новейший; меню зовёт apply в пунктах 2 и 3
backup check <файл> проверить файл копии базы

Настройки меняются в базе; панель берёт адрес, порт, путь и сертификат после перезапуска, меню перезапускает её само после каждого panel set.

Интерфейсы и клиенты

Команда Что делает
endpoint list интерфейсы с портом, адресами и тем, кто держит порт открытым: панель или хост
endpoint open <имя>, endpoint close <имя> держать порты интерфейса открытыми в брандмауэре или оставить хосту
endpoint default <имя> сделать интерфейс тем, на который встаёт новый клиент; endpoint list отмечает его словом default в конце строки
import endpoint <файл.conf> [--name <имя>] [--host <адрес>] [--dns <список>] [--allowed <список>] интерфейс из файла awg-quick, с ключами и обфускацией
import peers <файл.conf> [--endpoint <имя>] пиры файла интерфейса как клиенты без приватных ключей
import clients <файл.json> [--endpoint <имя>] [--v6 <префикс>] клиенты из файла, в котором хост держал их с приватными ключами
device list интерфейсы amneziawg в ядре
device show [имя] [--secrets] интерфейс с пирами, как его держит ядро
device set <имя> [--key <base64>] [--generate] [--port <n>] [--fwmark <n>] [--shape jc=4,jmin=40,...] [--i1 <спец>] [--hpk <base64>] записать настройки интерфейса в ядро напрямую, для отладки
device peer <имя> <публичный ключ> [--allowed <a,b>] [--endpoint <хост:порт>] [--preshared <base64>] [--keepalive <с>] [--replace-ips] [--update-only] [--remove] пир интерфейса в ядре, для отладки
family [имя] номер семейства netlink

Команды device и family говорят с ядром, минуя базу панели: что они изменили, панель при следующем применении положит обратно по своим настройкам. Клиенты, правила, каналы и шаблоны из консоли не редактируются: это HTTP API с токеном от token add.

Пресеты и шаблоны

Команда Что делает
preset list пресеты: сколько записей идёт через туннель, напрямую и в блок, сколько шаблонов их раздают, «по умолчанию», «только чтение» и пометка у пресета, созданного раньше в режиме «Всё через VPN»
preset set <имя> --readonly on | off флаг «Только чтение», см. Пресеты маршрутизации
template list шаблоны: сколько клиентов, какие пресеты и presets only у шаблона с флагом «Только списки сервера»
template set <имя> --presets-only on | off флаг «Только списки сервера»; у шаблона без пресетов отказ, см. Шаблоны

Гео и DNS

Команда Что делает
geo update скачать включённые гео-источники сейчас
dns show настройки DNS-сервера; строка for clients - что пишет в файлы выбор сервера «Предпочтительный DNS», строка files - сколько включённых клиентов держат файлы, где он назван
dns get enabled, port, upstreams, encrypted, outbound, files, files-dns, holders одно значение; encrypted - all, none или partly, спрашиваются ли внешние серверы шифрованно; files - выбор сервера для файлов, files-dns - его свои серверы; holders - сколько включённых клиентов держат файлы с DNS-сервером, см. Выданные файлы
dns set [--enabled auto | off] [--upstreams <серверы> | default] [--files <выбор>] [--files-dns <серверы>] дать DNS-серверу работать, пока он нужен маршрутизации (auto или on), или выключить его, задать внешние серверы или вернуть те, с которых начинает свежая панель; выключение называет, сколько клиентов с файлами, где назван DNS-сервер, останутся без ответов на имена. --files - выбор сервера для файлов: routing («Автоматически»), panel, network, own (с --files-dns), endpoint, см. Серверы имён в файле

Меню amneziageo-server dns on и dns off зовут то же с вопросами.

Пример

Токен на сутки, список клиентов через API и его отзыв:

amneziageo-server token add nightly --role admin --days 1
curl -s -H "Authorization: Bearer agt_..." https://panel.example.com:8443/api/clients
amneziageo-server token revoke <id> --yes

Все команды принимают --db <файл>, чтобы работать с другой базой, например с копией.
