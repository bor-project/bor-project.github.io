Сертификаты

Вкладка «Сертификаты» задаёт сертификат, под которым панель отвечает по HTTPS. С ним отвечают по TLS и TCP-порты сервисов интерфейсов и подписки на порту панели. Без сертификата панель отвечает открытым HTTP, а порты сервисов - под сертификатом, который панель делает себе при старте.

Поле Что задаёт
Домен сертификата каталог из /etc/letsencrypt/live: выбор домена заполняет два пути ниже его fullchain.pem и privkey.pem; «Без сертификата» снимает сертификат; «Свой путь» открывает поля для своих файлов
Путь к сертификату цепочка в PEM
Путь к ключу закрытый ключ этой цепочки, берётся вместе с ней

Сохранение читает оба файла и отказывает тому, который не загружается, с кодом, который называет файл; в силу сертификат вступает после «Перезапустить». Каталог доменов задаёт Web__CertificateRoot, /etc/letsencrypt/live по умолчанию. Файл перечитывается всякий раз, когда меняется на диске, так что продлённый сертификат берётся без перезапуска. Сертификат, которого при старте нет на диске, останавливает сервер.

Let’s Encrypt

Сертификат на имя сервера выпускает пункт 22 консольного меню SSL Certificate Management: он проверяет, что имя разрешается и TCP 80 свободен, ставит certbot, открывает 80 в ufw, выпускает сертификат с ключом RSA 2048 проверкой HTTP-01, включает таймер продления certbot.timer, ставит сертификат панели и предлагает открыть её на всех адресах хоста. То же делает вопрос об имени сервера при установке.

Ключ RSA нужен, чтобы цепочка доходила до корня ISRG Root X1, который есть во всех Android с 7.1; как проверить цепочку и перевести сертификат на RSA, см. рецепт Сертификат, которому верят старые Android. Файлы берутся по путям из live, не копиями: при продлении certbot обновляет ссылки в live, а панель перечитывает файл сама. Для продления имя должно указывать на сервер, а TCP 80 оставаться доступным снаружи: certbot слушает его только во время проверки.

Карточка «Службы» на Обзоре показывает каждый файл сертификата с датой окончания и предупреждает за 14 дней: «Истекает через N дн.».

Те же настройки в окружении панели: Web__Certificate и Web__CertificateKey; они действуют, пока панель не записала свой путь, см. Первый старт.

Сертификат, который берут не все клиенты

Подписка выключенаПока сертификат негоден, подписки выключены: клиенты их не скачают. Подписки отвечают только под сертификатом, который берут все клиенты. Негодным сертификат считается, когда:

  • его нет: порт сервисов интерфейса отвечает под сертификатом, который панель сделала себе сама, а свой порт подписок - открытым HTTP;
  • файл не читается или сертификат истёк;
  • он выдан не на имя из адреса подписки;
  • он подписан сам собой;
  • в файле нет сертификата, который его выдал: нужен fullchain.pem, а не cert.pem;
  • цепочка идёт к корню, которому хост не доверяет;
  • цепочка идёт к ISRG Root X2, которого нет в Android до 14-й версии, см. Сертификат, которому верят старые Android.

С таким сертификатом подписки отвечают 404, а свой порт подписок без сертификата не открывается. Hello работает при любом сертификате и говорит приложению AmneziaGeo, что подписка выключена: приложение показывает её со значком «!» и не читает. На вкладке «Экспорт» клиента лист «QR: подписка» остаётся только для чтения со значком «!» и подсказкой о причине, а карточка «Службы» на Обзоре называет причину в строке «Подписки» и в строке сертификата. Файл .conf и ссылка vpn:// выдаются и под негодным сертификатом панели, со значком «!»: на сервере без домена другой выдачи нет.
