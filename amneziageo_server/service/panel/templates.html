Templates

A template carries what in a client file does not belong to one client: AllowedIPs, name servers, the packet size and keepalive, and also the routing presets the AmneziaGeo app gets. A client points at a template rather than holding a copy: editing the template changes the files of all its clients, and a subscription serves the new file at once, because the file is assembled at the moment of the request. A fresh panel starts with the default template.

The “Templates” tab of the “Clients” page lists the templates with their AllowedIPs, DNS, MTU, keepalive and the number of clients, the row “Default” with the clients without a template first; the number leads to the list of the clients of the template, the name to the settings, the choice “Every preset” keeps the templates with one preset, “Add” opens a new one, “Duplicate” in the row menu makes a copy “<name> copy”; an icon at the name - the DNS settings of the template contradict, see Contradictions. The “Template” field in the settings of a client picks its template, “Default” leaves the client the settings of the interface.

Main

“Name”: up to 64 characters, one of a kind in the panel.

Clients

The “Clients” part names the clients of the template, a name leads to the settings of the client. The field adds a client: the offer names its present template in grey beside it, and the client leaves that template for this one. The cross takes a client off the template, and the client stays on “Default”. The changes are kept with the template by “Save”.

The “Default” page names the clients without a template. The field adds a client and takes its template off; a client is not taken off here: it gets another template in the settings of that template.

Routing

The entries of a template are what the client sends into the tunnel. Ranges are not written by hand: the template holds a list of entries, like the lists of the AmneziaGeo client, and unfolds them into addresses itself.

Entry Written as Gives
GeoIP geoip:ru the ranges of a country or a network from the geo databases
GeoSite geosite:youtube the addresses the domains of the category resolve to
Network cidr:10.0.0.0/8 itself
Address cidr:203.0.113.10 itself
Domain domain:example.com the addresses the name resolves to

A network, address or name typed without a prefix gets one as it is added; a link keeps its host. The names are asked in both families through the upstream servers of the DNS server of the panel; from a geosite category only domains and exact names are asked, since keywords and expressions have no address. One pass asks up to 4000 names and ends after a minute; a name without an answer counts as not found. Addresses a packet through the tunnel would not go to (loopback, zero, link-local, multicast, broadcast) are dropped; a private address stays, because a name of an internal DNS server may lead to a host behind the server.

What the entries gave is folded into the fewest ranges and kept with the template, together with the entries that gave nothing and the time of the pass: “Refreshed <time>”, “Nothing found for: <list>”. This is what goes into AllowedIPs of every client of the template; an empty list gives 0.0.0.0/0, and a client with an IPv6 address also gets ::/0. A name server of the file inside the network of the interface, the DNS server of the panel among them, answers only through the tunnel: when the ranges leave it out, it is added to AllowedIPs as a single address. The list is computed again on save, with the “Refresh” button, on its own once a day and right after the geo databases change: names move and the geo databases update, and the files of the clients change only after a new pass. When the name servers give no answer, the panel keeps the list it had and tries again in an hour.

While a template is being edited, the panel counts what each entry gives: “Addresses: N” on the entry and on the whole template, “Show what it holds” unfolds the first addresses or names of a category (“No entries: the category is absent from the downloaded databases”). Over 12000 ranges means “the speed may drop”, over 16000 “too many addresses to save”. A template holds no more than 256 entries.

“Routing presets” are the lists the AmneziaGeo app of a client of the template gets, in the order of handing out, while routing happens on the client; the name of a preset leads to its settings, see Routing presets; “No presets: add them in the tab Routing presets” while none are made.

Route by name

A client with nothing but AllowedIPs cannot follow a name. A service behind a CDN answers with the cache nearest to whoever asks; the caches stand in the networks of providers and change, and neither the addresses a pass found nor the geo ranges of the service cover them. With the “Route by name” switch in the “Routing” part, the names of the template (geosite: and domain:) are not unfolded into addresses, and such entries show “by name” instead of a number of addresses. The DNS server of the panel answers a client of the template about these names with a stand-in address out of 198.19.0.0/16: one address per name, the same for as long as the name is asked about, and the same on every server as long as two names do not land on one address. The host leads a connection to the stand-in to the real address the DNS server got for the name and decides it by the real one, so the rules of the server see such a connection as any other, see Stand-in addresses.

The file of such a client carries the DNS server of the panel as its only name server (the “DNS” field of the “Network” part stands at “Panel DNS server” and cannot be edited), and in AllowedIPs the networks and addresses of the template, 198.19.0.0/16 and the address of the DNS server. A geo key of addresses (geoip:) stays a range: it serves the applications that go to addresses without asking a name, Telegram and calls among them.

The switch works while the DNS server of the panel answers the clients on port 53 and the firewall of the host lets them reach it. The template is saved with the switch on in any case, and the form under it names what keeps it from working, with the command that mends it:

Message What to do
Will not work: the DNS server is off set it to “Automatic” on the DNS page, with sudo amneziageo-server dns on or with menu item 29
Will not work: the panel DNS server answers on port N, while the clients ask on 53 set port 53 on the DNS page
Routing by name does not work for the clients of <interfaces>: the server firewall keeps them from the DNS server of the panel on the server sudo amneziageo-server dns open, menu item 23, sub-item 13, or sudo ufw allow in on <interface> to any port 53 for each interface

An application with name servers of its own goes past the stand-ins; the guard of the DNS server resets the known public servers of DoT and DoH for the clients, see Questions of the clients. A name with a stand-in gets no IPv6 answer and no HTTPS record, so the client goes to it over IPv4. A stand-in that leads nowhere, after a client came over from another server or for a name nobody asked about for a week, is refused at once, and the client asks for the name again.

Removing

A template taken by at least one client is not removed: “The template is in use”. The removal page names these clients; first they are taken off the template in its settings.
