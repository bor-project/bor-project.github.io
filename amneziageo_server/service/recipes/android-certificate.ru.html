Сертификат, которому верят старые Android

Задача: Android до 14-й версии не открывает панель или подписку сервера, хотя с компьютера и с нового телефона всё работает. Почти всегда дело в цепочке сертификата: она кончается на корне ISRG Root X2, которого в этих телефонах нет. Есть в них ISRG Root X1, и цепочка должна доходить до него.

1. Признаки

  • Браузер на Android до 14 пишет, что подключение не защищено, и не открывает панель или страницу подписки.
  • Приложения, которые сами скачивают подписку, отвечают ошибкой соединения.
  • Карточка «Службы» на Обзоре пишет в строке «Подписки» и в строке сертификата «цепочка до ISRG Root X2: Android до 14 не скачает подписку».

Под такой цепочкой подписки выключены для всех клиентов, а приложение AmneziaGeo показывает подписку со значком «!», см. Сертификат, который берут не все клиенты.

2. Проверка цепочки

Команда проверяет цепочку с любой машины, где есть OpenSSL, и с самого сервера тоже. Вместо <имя> подставьте имя сервера, вместо <порт> - порт панели или порт из адреса подписки:

openssl s_client -connect <имя>:<порт> -servername <имя> < /dev/null 2> /dev/null | grep -E '^ +[0-9]+ s:|^ +i:'

Строки s: называют сертификаты цепочки, строки i: - тех, кто их выдал. Смотрите на последнюю строку i::

  • ISRG Root X1 - хорошо: этот корень есть во всех Android с 7.1;
  • ISRG Root X2 или Root YE - плохо: Android до 14 такую цепочку не примет.

Хороший ответ, ключ RSA:

 0 s:CN=vpn.example.org
   i:C=US, O=Let's Encrypt, CN=YR1
 1 s:C=US, O=Let's Encrypt, CN=YR1
   i:C=US, O=ISRG, CN=Root YR
 2 s:C=US, O=ISRG, CN=Root YR
   i:C=US, O=Internet Security Research Group, CN=ISRG Root X1

Плохой ответ, ключ ECDSA с короткой цепочкой:

 0 s:CN=vpn.example.org
   i:C=US, O=Let's Encrypt, CN=YE1
 1 s:C=US, O=Let's Encrypt, CN=YE1
   i:C=US, O=ISRG, CN=Root YE
 2 s:C=US, O=ISRG, CN=Root YE
   i:C=US, O=Internet Security Research Group, CN=ISRG Root X2

Цепочка Let’s Encrypt по умолчанию доходит до ISRG Root X1 и у ключа RSA, и у ключа ECDSA. У ECDSA в ней на одно звено больше: за ISRG Root X2 идёт он же, подписанный ISRG Root X1. Плохую цепочку дают короткая цепочка, которую выбрали при выпуске (у certbot это --preferred-chain), и программа, которая выбирает цепочку сама. Цепочка ключа RSA обходится без ISRG Root X2, поэтому меню выпускает RSA.

Если на порту отвечает не панель, а nginx, 3x-ui или другой прокси, команда показывает его сертификат, и чинить нужно его.

Тип ключа сертификата на хосте называет строка Key Type в выводе certbot certificates. Его же печатает подпункт «Сертификаты» пункта 22 консольного меню.

3. Сертификат RSA от certbot

Пункт 22 меню SSL Certificate Management, подпункт «получить сертификат Let’s Encrypt», выпускает сертификат с ключом RSA 2048. Если сертификат с тем же именем уже есть и у него ключ ECDSA, меню выпускает его заново. Руками на хосте:

certbot certonly --standalone --preferred-challenges http --key-type rsa --rsa-key-size 2048 --cert-name <имя> -d <имя>

Уже выпущенный сертификат с ключом ECDSA переводит на RSA та же команда с --force-renewal. Тип ключа certbot записывает в /etc/letsencrypt/renewal/<имя>.conf (key_type = rsa), и продление его сохраняет. certbot до версии 1.10 ключа --key-type не знает и выпускает RSA сам.

Перезапуск не нужен: панель перечитывает сертификат, когда файл меняется на диске. Сертификат не из /etc/letsencrypt/live ставится на вкладке Сертификаты.

4. Сертификат от другой программы

  • acme.sh (через него выпускает сертификат и 3x-ui) по умолчанию выпускает ключ ECDSA ec-256, ключ RSA - с --keylength 2048. Сертификат ECDSA лежит в каталоге <имя>_ecc, сертификат RSA - в каталоге <имя>. После выпуска заново отдайте серверу новые файлы (--install-cert).
  • Caddy по умолчанию выпускает ключ ECDSA P-256, ключ RSA - с key_type rsa2048 в глобальных настройках или в блоке tls.
  • Другая программа: выпустите ключ RSA 2048 или проверкой из раздела 2 убедитесь, что последней строкой i: идёт ISRG Root X1.

5. Проверка

Команда из раздела 2 на каждом порту, где сервер отвечает по TLS, последней строкой i: называет ISRG Root X1. Карточка «Службы» на Обзоре больше не называет причину в строке «Подписки» и в строке сертификата.
