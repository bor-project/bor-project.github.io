Выход через другой сервер

Задача: клиенты подключаются к этому серверу, а сайты из списка открываются через другой сервер, например за границей. Этот сервер становится клиентом того и отправляет в туннель только то, что подошло под правило; остальное идёт через хост как раньше.

1. Конфигурация клиента на другом сервере

На другом сервере нужна конфигурация клиента для этого хоста. На сервере AmneziaGeo это «Клиенты» > «Добавить», имя вроде relay-home, и файл .conf с вкладки «Экспорт». Подойдёт любой сервер AmneziaWG или WireGuard, который выдаёт файл клиента.

2. Канал

«Маршрутизация» > «Каналы» > «Добавить»:

  1. Тип «AmneziaWG».
  2. Внизу формы вставьте файл клиента в поле «Конфигурация клиента» и нажмите «Прочитать»: ключи, адрес интерфейса, сервер с портом и обфускация заполнятся из него.
  3. «Имя» - до 15 знаков, например awg-de.
  4. «Проверка доступности»: «Сервер имён» 1.1.1.1, «Период, с» 30. Вопрос уходит через туннель, и ответ значит, что туннель жив.
  5. «Закрыть частные сети» оставьте включённым: клиенты не попадут в сеть за тем сервером.
  6. «Сохранить».

Через несколько секунд в списке у канала стоит «готов», рукопожатие и трафик. «Отказ» с причиной значит, что хост не поднял интерфейс; «рукопожатия не было» - сервер не ответил: проверьте адрес, порт и обфускацию, они должны совпадать с сервером точно.

Если сеть до того сервера пропускает только веб-трафик, тип «WebSocket» и поле «Прокси websocket»: для сервера AmneziaGeo это wss://<его хост>:<порт сервисов>/<путь WebSocket интерфейса>, путь виден в форме его интерфейса.

3. Резолвер

Правило по доменам работает через резолвер панели: «Маршрутизация» > «DNS», «Отвечать клиентам» включено, «Спрашивать через канал» - awg-de, чтобы адреса приходили оттуда, куда пойдёт трафик, «Сохранить» и «Перезапустить» в шапке. Если резолвер ещё не включали, его включает и пункт 29 консольного меню.

4. Правило

«Маршрутизация» > «Правила» > «Добавить»:

  1. «Имя» abroad, «Действие» «Через канал», «Канал» awg-de.
  2. «Куда»: ключи и домены, которые должны идти через тот сервер, например geosite:youtube, geoip:ag-youtube, geosite:netflix, example.com. Что несёт ключ, подсказывает «Показать содержимое» в шаблонах и справка по Спискам Geo.
  3. «Включено», «Сохранить».

Пока туннель до того сервера лежит, трафик правила отбрасывается, а не уходит через хост под адресом этого сервера.

В списке у правила «на хосте» и число диапазонов и имён. Правило стоит в порядке чтения: если выше есть правило, которое берёт тот же трафик, переставьте стрелками.

5. Проверка

«Маршрутизация» > «Проверка»: «Имя или адрес» youtube.com, «Порт» 443, «Клиент» любой клиент панели, «Проверить». Итог «Через канал awg-de» и правило abroad со «сработало» по имени или диапазону. С устройства клиента откройте сайт из списка и любой другой: первый видит адрес того сервера, второй - этого.

Если не работает

  • Правило «трафик заперт»: канал ничего не несёт, см. его состояние. Пока проверка доступности не проходит, группа и правила считают канал мёртвым.
  • Сайт открывается через хост: правило выше по списку взяло трафик раньше, или имя не попало в наборы. «Проверка» называет правило и то, по чему оно сработало; «Адресов в наборах» на странице DNS растёт с ответами резолвера.
  • Другой сервер AmneziaGeo с собственными правилами по именам сбрасывает DNS через HTTPS от этого, пока не отпустит его после трёх попыток: чтобы вопросы шли сразу, назовите внешний сервер здесь открытым DNS (1.1.1.1) и спрашивайте через канал, тот сервер примет вопрос своим резолвером, см. DNS.
